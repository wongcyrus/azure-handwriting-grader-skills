Technical reading and prompt conventions

The central subject is the agent skill, not a sequence of commands for the teacher to memorize. Each article includes a relevant verbatim SKILL.md excerpt, explains how the assistant chooses tools from intent and workspace state, and distinguishes that behavior from Python validation and Framework execution. Python excerpts are explained in terms of their inputs, branches, returned objects and failure conditions; production prompts explain the purpose and limits of their clauses rather than appearing as unexplained copy/paste blocks.

There are three instruction layers: teacher intent, reusable skill guidance, and application-generated Azure task prompts. Framework's typed "grade" message is control data, not a fourth model prompt. The inspected Framework module does not load SKILL.md; the host assistant invokes the Python CLI, which selects the default Framework runtime. Skill instructions alone do not enforce approval.

Illustrative teacher requests and expected skill-guided decisions are not captured agent conversations. Actual screenshots/exports and console outputs remain separately labelled. Template placeholders show runtime insertion; they are not asserted historical HTTP payloads. The scan-check stop rule belongs to skill-guided preparation; the inspected grading route does not automatically rerun that check.

Banner-generation prompts, code and costs belong only to the editorial branding documentation, not the eight grading articles. The artwork and provenance are retained; removing the unrelated appendices requires no new image request.

Part 6 includes a new real Framework execution with synthetic validation/grading stubs and an explicitly forbidden Azure client, alongside its complete script and captured output. It demonstrates typed sequencing without a paid grading run or alteration of the example. It is not a historical exam event trace.
